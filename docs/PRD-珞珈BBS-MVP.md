## 1. 产品概述

### 1.1 背景与机会

武汉大学目前缺少一个统一的、专门服务于本校师生的社区平台。学生的信息需求（闲置交易、课程评价、考研经验、求职内推、校园社交）分散在微信群、QQ 群、贴吧、微博超话等零散渠道中，存在以下问题：

- **信息碎片化**：同类信息散落在上百个群聊中，难以沉淀、检索与复用。
- **信任成本高**：二手交易、招聘内推等场景缺乏身份背书，交易与信息可信度低。
- **优质内容被淹没**：考研经验、课程评价等长文内容在即时通讯工具中无法长期保存和传播。
- **缺乏归属感**：没有一个真正属于武大人自己的、可持续运营的社区。

**珞珈BBS 的定位**：一个专属于武汉大学的、有序的、可持续沉淀优质内容的校内社区。

### 1.2 产品定位

> 珞珈BBS 是武汉大学师生专属的校内社区，以「板块」为组织单元，以「帖子」为内容单元，让信息有序、让优质内容沉淀、让同学彼此信任。

一句话：**一个不乱的、有武大归属感的校内 BBS。**

### 1.3 目标用户

| 用户类型 | 描述 | 核心诉求 |
| --- | --- | --- |
| 在校本科生 | 主力用户，活跃于二手交易、课程评价、考研、校园社交 | 快速找到有用信息、低成本交易、认识同学 |
| 研究生 / 博士生 | 学术、科研、租房、就业、相亲交友 | 学术互助、职业信息、生活服务 |
| 教职工 | 校内事务、招聘、发布公告 | 触达学生、发布权威信息 |

MVP 阶段以 **在校学生** 为核心用户，教职工作为次级用户。

### 1.4 核心价值主张

1. **信息有序**：清晰的板块分类 + 标签体系 + 内容排序策略，杜绝信息瀑布。
2. **内容可信**：身份认证 + 内容治理机制，降低交易与信息信任成本。
3. **内容沉淀**：优质长文（经验帖、评价帖）可被检索、收藏、复用。
4. **归属感**：专属武大的社区身份与氛围，形成「武大人自己的社区」认同。

## 2. 产品设计原则

本产品的「高级感」不体现在视觉，而体现在**信息秩序、内容质量与克制的功能边界**上。以下五条原则贯穿所有功能设计：

1. **有序优先（Order First）**：任何信息必须先归类再呈现。首页不做信息瀑布，板块内不做无规则的混排。
2. **质量优先（Quality over Volume）**：通过精华机制、排序策略与审核，让优质内容被看见，而非让所有内容平等刷屏。
3. **信任优先（Trust First）**：身份认证与内容治理是社区的地基，交易、社交等场景建立在其上。
4. **克制（Restraint）**：MVP 只做「浏览—发帖—回复—互动」这条核心链路，避免功能堆砌。
5. **身份一致（One Identity）**：小程序与 Web 共享同一套账户、数据与身份，两端体验连贯。

## 3. 用户画像与核心场景

### 3.1 典型用户画像

**画像 A：考研的小周（大三，计算机学院）**
- 需求：找武大各学院的考研报录比、专业课复习资料、上岸学长学姐经验。
- 痛点：信息散在贴吧和群里，真假难辨，找不到针对性强的经验帖。

**画像 B：出闲置的小林（大四，经济与管理学院）**
- 需求：毕业前出掉教材、台灯、自行车等闲置。
- 痛点：在群里发消息被刷掉、买家身份不明、线下交易有顾虑。

**画像 C：想找实习的小陈（研一，法学院）**
- 需求：找师兄师姐的内推机会、面经、实习避坑。
- 痛点：内推信息分散，缺少可信的渠道。

**画像 D：想脱单的小王（大二）**
- 需求：在校园范围内认识同学。
- 痛点：缺少一个真实、低门槛、有边界的校园社交场景。

### 3.2 核心使用场景

| 场景 | 用户行为 | 对应功能 |
| --- | --- | --- |
| 二手交易 | 发布闲置 → 买家咨询 → 线下交易 | 发帖、回复、身份认证 |
| 考研互助 | 搜索经验帖 → 收藏 → 回复提问 | 搜索、收藏、回复 |
| 课程评价 | 选课前查看评价 → 课后写评价 | 板块浏览、发帖、标签 |
| 求职内推 | 浏览招聘信息 → 回复联系 | 板块浏览、回复 |
| 校园社交 | 浏览交友板块 → 互动 | 板块浏览、回复、点赞 |

## 4. 信息架构

信息架构是本产品「有序」的核心载体，采用 **「分类 → 板块 → 标签 → 帖子」** 四层结构。

### 4.1 全局信息结构

```
珞珈BBS
├── 首页（广场）
├── 板块（按分类聚合）
├── 搜索
├── 通知
└── 我的（个人中心）
```

### 4.2 板块分类体系（MVP）

板块是内容的第一组织单元。MVP 设置 **5 大分类、17 个板块**：

| 分类 | 板块 | 说明 | MVP 状态 |
| --- | --- | --- | --- |
| **校园生活** | 二手市场 | 闲置交易（出/求/租） | 核心 |
| | 失物招领 | 寻物、寻主 | 核心 |
| | 校园互助 | 跑腿、拼车、求助 | 核心 |
| | 校园热点 | 校内新闻、活动、讨论 | 核心 |
| **学习成长** | 课程评价 | 课程与教师评价（匿名可选） | 核心 |
| | 考研专区 | 考研信息、经验、资料 | 核心 |
| | 保研出国 | 保研、留学申请经验 | 核心 |
| | 竞赛组队 | 学科竞赛组队、找队友 | 核心 |
| | 学术讨论 | 科研、论文、学术交流 | 次要 |
| **职业发展** | 校招实习 | 校招与实习招聘信息 | 核心 |
| | 内推专区 | 内推机会、求内推 | 核心 |
| | 求职经验 | 面经、简历、求职避坑 | 核心 |
| | 毕业去向 | 毕业去向与就业薪资分享 | 核心 |
| **社交娱乐** | 校园恋爱 | 交友、脱单 | 核心 |
| | 兴趣社团 | 社团、同好、活动 | 次要 |
| | 树洞 | 匿名倾诉（全站匿名） | 核心 |
| **站务** | 站务公告 | 官方公告、规则、反馈 | 核心 |

> 板块数量在 MVP 阶段刻意保持克制（17 个），避免因板块过多导致信息再次分散。后续根据数据反馈新增板块。

**「毕业去向」板块特殊规则**（薪资分享敏感，MVP 前置约束）：

1. **默认匿名**：薪资类发帖默认匿名，降低分享者心理门槛；作者真实身份仅运营后台可见，前台不展示。
2. **口径必填**：发帖需填写「学历 / 专业 / 城市 / 企业类型」等口径字段（模板化），否则薪资数字之间失去可比性，信息失真。

### 4.3 内容标签体系

板块内部通过**标签**进行二级分类，进一步保证信息有序。标签由运营预置（部分板块允许发帖者选择），MVP 不开放自由创建标签。

| 板块 | 预置标签（示例） |
| --- | --- |
| 二手市场 | `出` / `求` / `租` |
| 课程评价 | 按学院/课程归属（如 `计院` / `经管`） |
| 考研专区 | `数学` / `英语` / `政治` / `专业课` / `经验` / `资料` |
| 竞赛组队 | `数模` / `ACM` / `挑战杯` / `互联网+` / `其他` |
| 校招实习 | `校招` / `实习` / `宣讲会` |
| 内推专区 | `内推` / `求内推` |
| 求职经验 | `面经` / `简历` / `避坑` |
| 毕业去向 | `就业` / `深造` / `薪资` |
| 校园恋爱 | `交友` / `脱单` / `情感` |

### 4.4 内容层级与状态

每篇帖子在列表中有明确的状态标识，避免「信息堆在一起无法区分」：

| 层级 | 含义 | 展示方式 |
| --- | --- | --- |
| 置顶 | 运营/版主置顶的公告或重要内容 | 列表顶部，常驻 |
| 精华 | 高质量内容，人工或规则加精 | 列表带「精」标识，可筛 |
| 普通 | 常规帖子 | 默认展示 |

帖子必含字段：**标题、板块、标签（可选）、正文、作者、发布时间、互动数据（浏览/回复/点赞）**。

## 6. 内容排序与推荐策略

「信息有序」不仅是分类，更体现在**排序**上。MVP 排序策略：

1. **帖子列表综合排序**：综合「热度 + 新鲜度 + 互动率」计算，权重由运营可调。热度公式参考：`互动数(回复×3 + 点赞×2 + 浏览×0.1) / 时间衰减因子`。
2. **精华优先**：精华帖在列表中获得更高排序权重，且首页精选流优先收录。
3. **首页精选流**：由「人工精选 + 规则推荐」结合，人工精选保证质量底线，规则推荐保证更新量。
4. **杜绝纯时间刷屏**：默认排序不为纯时间倒序，避免优质长文被高频短帖淹没。

## 7. 双端差异（小程序 vs Web）

两端共享同一套账户、数据与板块结构，差异仅在场景适配：

| 维度 | 微信小程序 | Web 网站 |
| --- | --- | --- |
| 核心场景 | 移动浏览、拍照发二手、碎片时间回复 | 长篇阅读、考研/课程长文撰写、深度搜索 |
| 登录方式 | 微信授权一键登录 | 微信扫码 + 手机号 |
| 内容侧重 | 图片驱动（二手、树洞）、快速互动 | 长文驱动（经验帖、评价帖） |
| 传播方式 | 微信分享（帖子卡片、好友/群/朋友圈） | URL 分享、SEO 可检索 |
| MVP 优先级 | P0（先发） | P0（与小程序同步，功能对齐） |

> MVP 两端功能对齐（同一套 PRD 功能清单），避免两端能力割裂。差异仅在交互适配与内容呈现侧重。

## 8. MVP 范围

MVP 聚焦一条完整的内容闭环，仅包含以下能力：

- 板块化 BBS 核心链路：浏览、发帖、回复、互动、通知
- 身份认证（学生认证）
- 内容治理（审核、举报、禁言）
- 双端（小程序 + Web）对齐

## 9. 成功指标（MVP 验证目标）

MVP 的核心目标是**验证「有序社区」能否被武大学生接受并自发使用**。

| 指标 | 定义 | MVP 目标（示例） |
| --- | --- | --- |
| 注册转化 | 认证用户数 / 访问用户数 | 访问→认证 ≥ 40% |
| 内容活跃 | 日均发帖数、日均回复数 | 日均发帖 ≥ 100，回复 ≥ 500 |
| 用户留存 | 次日/7日留存 | 次日 ≥ 35%，7日 ≥ 20% |
| 优质内容沉淀 | 精华帖占比、收藏率 | 精华帖占比 ≥ 5% |
| 信任转化 | 二手市场成交反馈、举报处理时效 | 举报 24h 内处理率 ≥ 90% |

> 数值为初版假设，上线后根据真实数据校准。

## 10. 风险与开放问题

| 风险/问题 | 说明 | 应对 |
| --- | --- | --- |
| 内容冷启动 | 新社区初期无内容，用户来了没得看 | 运营预置种子内容（考研资料、课程评价、二手引导帖），邀请种子用户 |
